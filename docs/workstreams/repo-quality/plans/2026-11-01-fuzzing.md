# Fuzzing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Native Go fuzz targets with stated properties over identifier quoting, literal escaping,
the OPA mask path and the REPL's input parsing, a `make fuzz` that runs them all, and a CI fuzz
job that runs only on schedule and direct dispatch.

**Architecture:** A dependency-free test-support lexer (`internal/sqllex`) reads rendered SQL back
under each dialect's quoting rules, so a property is checked against an independent reading of the
output rather than against the code that wrote it. Targets live beside the code they fuzz. One
script (`scripts/fuzz.sh`) enumerates and runs every target, and both `make fuzz` and the CI job
call it. The CI gate's skip table learns `fuzz`.

**Tech Stack:** Go 1.27 native fuzzing (`testing.F`), bash, GitHub Actions, jq.

**Spec:** `docs/workstreams/repo-quality/units/06-fuzzing.md` (Items, Acceptance criteria, and the
operator rulings in its Decisions).

## Global Constraints

- Targets are `func FuzzXxx(f *testing.F)` with seeds added via `f.Add`. Seeds run in every
  `go test` run. No committed `testdata/fuzz/` corpus files: `f.Add` covers every seed, so the CI
  artifact holds only new failures.
- Each target asserts a property, written in the table below, and not only "does not panic".
- `make fuzz FUZZTIME=<d>` runs every target in turn. The default is `10s`.
- CI fuzz job: runs only on `schedule` (5m per target) and direct `workflow_dispatch` (15s per
  target), never on `pull_request`, `push` or a `workflow_call` from release.yml (operator ruling).
  It uploads `**/testdata/fuzz/**` on failure with `retention-days: 14`, uses
  `persist-credentials: false` and `ref: ${{ inputs.ref }}` on checkout, and pins every action by
  SHA. Its timeout is sized to the target count.
- `scripts/ci-result.sh`: `fuzz` may be skipped on `pull_request`, `push` and `workflow_call`, and
  never on `schedule` or `workflow_dispatch`.
- A real defect found by fuzzing is not fixed in this unit. A vulnerability goes to the operator for
  a private security advisory. Any other defect goes under the brief's `## Not done, and why` with
  its failing input, and the target stays with that input skipped and a reason given.
- Known defect (operator ruling): `quoting.EscapeString` doubles `\` for every dialect. The
  PostgreSQL and SQLite round trip is asserted only for backslash-free input. The `\` case is a
  `t.Skip` test naming the defect.
- House commit rules: subjects in past tense, no agent attribution, 60 characters at most, signed
  through the git-guard hook as one plain `git commit -F <file>` call, never on the default branch,
  never pushed. Australian English, and no em dashes.
- golangci-lint, zizmor (`uvx zizmor@1.31.1`), shellcheck and `scripts/wombat-verify.sh` must pass.
  CHANGELOG.md gets an `[Unreleased]` entry.

## Targets and their properties

| Target | Package | Property |
|---|---|---|
| `FuzzDoubleQuote` | `internal/quoting` | `sqllex.Lex(ANSI, DoubleQuote(s))` is exactly one `Ident` token whose value is `s` (round trip, and no early close) |
| `FuzzBacktick` | `internal/quoting` | the same under `MySQL` for `Backtick(s)` |
| `FuzzEscapeString` | `internal/quoting` | `"'"+EscapeString(s)+"'"` lexes to exactly one `String` token under both lexers (no early close under either). Under `MySQL` its value is `s`. Under `ANSI` its value is `s` when `s` has no `\` |
| `FuzzEscapeLikePattern` | `internal/quoting` | unescaping the result (`\x` gives `x`) yields `s`, and no `%` or `_` in the result is unescaped |
| `FuzzIdentifierQuoting` | `visitors` | for each of the three visitors, `SELECT` of column `c` from table `t` (both fuzzed) lexes so that the identifier tokens, in order, are exactly `t, c, t` (qualifier, column, FROM table) |
| `FuzzStringLiteral` | `visitors` | for each visitor with `WithoutParams()`, `WHERE t.c = Literal(s)` lexes to a token stream ending in exactly one `String` token. Its value is `s` under MySQL, and under PostgreSQL and SQLite when `s` has no `\`. With params on (the default), the SQL contains no `String` token and `Params()` is exactly `[s]` |
| `FuzzMaskedProjection` | `plugins/opa` | with a mask value `v` on column `col`, the transformed core rendered by each visitor with params has `Params()` exactly `[v]` and the alias lexes to an `Ident` whose value is `col`. Without params, it has exactly one `String` token, whose value is `v` under MySQL (and under ANSI when `v` has no `\`) |
| `FuzzTokenize` | `cmd/repl` | no token is empty; the tokens joined, with spaces and tabs removed, equal the input with spaces and tabs removed; and for any `s`, `tokenize("x = " + q)` with `q = "'" + strings.ReplaceAll(s, "'", "''") + "'"` is exactly `["x", "=", q]` |
| `FuzzParseValue` | `cmd/repl` | `parseValue("'" + strings.ReplaceAll(s, "'", "''") + "'")` returns `s` with no error |

That is 9 targets. Schedule time is 9 x 5m = 45m, so `timeout-minutes: 60` (the 45m plus 15m for
compiling each package's fuzz binary and the corpus minimisation on failure).

## Review lanes this plan is held to

Every task is judged by the close's three lanes (`reviewLanes`). State them to every implementer:

- **security**: what an attacker or a hostile input could do with this change: secrets, injection,
  authorisation, and anything it exposes that was not exposed before.
- **correctness**: whether the code does what it claims under the cases it will actually meet,
  including the edges, the errors and the concurrent ones.
- **brief**: does this deliver what the brief (`units/06-fuzzing.md`) specified, criterion by
  criterion, including the operator rulings in its Decisions.

## Review Focus

1. Invalid UTF-8 and NUL bytes in identifiers and literals: the lexer works on bytes, so a target
   must not reject them. Each quoting and visitor target gets an `f.Add` seed of `"\xff\x00"`.
2. A mask value or literal that looks like a placeholder (`$1`, `?`): in params mode it must still
   arrive in `Params()`, never be read as a bind. Seeds `"$1"` and `"?"` in `FuzzMaskedProjection`
   and `FuzzStringLiteral`.
3. Empty strings, for both identifiers and values: seed `""` everywhere.
4. A `FUZZTIME` that is malformed or empty: `fuzz.sh` refuses it with a clear message rather than
   passing it to `go test`. `fuzz_test.sh` case `bad_fuzztime_refused`.
5. A target added later without a timeout bump: `ci-result_test.sh` case `ci_yml_fuzz_timeout_sized`
   fails when `timeout-minutes` is below `targets x 5 + 10`.

### Task 1: `internal/sqllex`, the read-back lexer

**Files:**
- Create: `internal/sqllex/sqllex.go`
- Test: `internal/sqllex/sqllex_test.go`

**Interfaces:**
- Produces:
  - `type Dialect int` with constants `ANSI` (`"` identifiers, `'` strings with `''` only) and
    `MySQL` (`` ` `` identifiers with ``` `` ``` doubling, `'` strings with `''` and backslash
    escapes: `\x` decodes to `x` for every byte `x`. That is a deliberate simplification that is
    exact for the output EscapeString produces).
  - `type Kind int` with `Ident`, `String`, `Other`.
  - `type Token struct { Kind Kind; Value string }`. Value is decoded for `Ident` and `String`, and
    a maximal run of non-quote, non-space bytes for `Other`.
  - `func Lex(d Dialect, sql string) ([]Token, error)`. It errors on an unterminated quote, or on a
    dangling `\` at the end under MySQL. Spaces separate `Other` runs and are dropped.
  - `func Of(ts []Token, k Kind) []string`, the values of every token of kind k, in order.

- [ ] **Step 1: Write the failing tests** `TestLex` (table): `ANSI` `"a""b"` gives `[{Ident a"b}]`;
  `ANSI` `'it''s'` gives `[{String it's}]`; `ANSI` `'a\'` gives `[{String a\}]`; `MySQL` `'a\'b'`
  gives `[{String a'b}]`; `MySQL` `` `x``y` `` gives `[{Ident x`y}]`; `ANSI` `SELECT "t".* FROM "t"`
  gives `Other SELECT, Ident t, Other .*, Other FROM, Ident t`. `TestLexErrors`: unterminated
  `"a`, `'a`, `` `a ``, and `MySQL` `'a\`. `TestOf`.
- [ ] **Step 2: Run** `go test ./internal/sqllex/` and expect FAIL (package does not build).
- [ ] **Step 3: Implement** `Lex` as a single byte loop. Note `.` and `*` adjoining an identifier

- Produces:
